# rtl-speech-recog

**Project Overview:**

- **rtl-speech-recog**: A small end-to-end repository that demonstrates MFCC feature extraction implemented in RTL (Verilog) and supporting Python tools for dataset preparation, ROM generation and reference MFCC computation. The RTL pipeline converts a 1-second audio clip (16 kHz) into a 32x13 MFCC feature grid suitable for a tiny CNN keyword-spotting classifier.

**Repository Structure:**

- **`*.py`**: Python utilities for data preparation, ROM generation and reference model training.

  - `wav_to_pcm16.py`: Load a WAV file and write 16-bit PCM samples to `audio_samples.txt` for use in simulations.
  - `dec_to_hex.py`: Convert decimal PCM samples in `audio_samples.txt` to a hex file (`audio_samples.hex`) used by the Verilog testbench.
  - `generate_roms_and_ref_2048.py`: Generates ROMs used by the RTL pipeline (`roms/window.hex`, `roms/mel_weights.hex`, `roms/dct.hex`, `roms/log_lut.hex`, `roms/twiddle.hex`, `roms/frame.hex`) and a reference MFCC file `roms/ref_mfcc.txt` using `librosa`.
  - `speech_recogn.py`: A Colab-derived script that shows how to compute MFCCs, train a small CNN (`tinyconv_kws_model.h5`) on a subset of the Speech Commands dataset and run inference.

- **`*.v` / `*.vhd`**: RTL and wrappers.

  - `mfcc_top.v`: Top-level RTL that orchestrates the whole pipeline: sample capture → windowing → FFT wrapper → magnitude → mel filterbank → log LUT → DCT → stream MFCCs (32 frames × 13 coeffs).
  - `windowing.v`: Maintains a 2048-sample sliding window, multiplies samples by a window (ROM `roms/window.hex`) and streams frames every hop (512).
  - `fft_ip_wrap.v`: Wrapper for the vendor FFT IP (`xfft_0`), packs windowed samples and unpacks AXI-stream outputs to `fft_real`, `fft_imag` (32-bit sign-extended).
  - `mel_bank_40.v`: Accumulates FFT magnitudes with mel weights from `roms/mel_weights.hex` to produce 40 mel energies.
  - `log_lut.v`: Synthesizable LUT-based natural log approximation (reads `roms/log_lut.hex`).
  - `dct_13x40.v`: DCT stage that converts 40 log-mel energies into 13 MFCC coefficients using `roms/dct.hex`.
  - `tb_mfcc.v`: A testbench that reads `python/audio_samples.hex`, feeds 16000 samples to `mfcc_top` and writes MFCC outputs to `mfcc_output.txt`.

- **Other files**:
  - `roms/` (generated by `generate_roms_and_ref_2048.py`): ROM hex files used by the RTL.
  - `speech_recog.h5`: (If present) trained model artifact.

**How it works (high-level):**

- Input: 1-second 16 kHz audio clip (16,000 samples).
- Preprocessing: Convert WAV to PCM (`wav_to_pcm16.py`) → decimal samples in `audio_samples.txt` → hex lines with `dec_to_hex.py` for the Verilog TB.
- RTL pipeline (per 1s clip):
  1.  `windowing.v` captures and streams overlapping frames (N=2048, hop=512) after applying a Hann window (Q1.15).
  2.  `fft_ip_wrap.v` sends frames to the FFT IP and receives complex bins.
  3.  `magnitude_approx` (expected in repo or provided externally) computes magnitudes from complex outputs.
  4.  `mel_bank_40.v` multiplies magnitudes by mel weights (`roms/mel_weights.hex`), producing 40 mel energies per frame.
  5.  `log_lut.v` approximates natural log using a LUT (`roms/log_lut.hex`).
  6.  `dct_13x40.v` computes 13 MFCC coefficients from 40 log-mel values (`roms/dct.hex`).
  7.  `mfcc_top.v` collects and streams MFCCs: 32 frames × 13 coeffs.

**ROMs & Fixed-point formats:**

- `window.hex`: Window coefficients (Hann) quantized Q1.15 (signed 16-bit).
- `mel_weights.hex`: Mel filterbank weights quantized Q1.15 (signed 16-bit). Stored row-major (40 × 1025 entries).
- `dct.hex`: DCT basis matrix quantized Q1.15 (13 × 40 entries).
- `log_lut.hex`: Log lookup table values quantized Q6.10 (signed 16-bit). Used by `log_lut.v`.
- `twiddle.hex`: Optional FFT twiddle pairs (Q1.31) when a custom FFT is used.
- `frame.hex`: Sample frame example (1s test frame) quantized to 16-bit PCM.

Notes on Q-formats used in RTL:

- Q1.15: 1 sign bit, 0 integer bits, 15 fractional bits (commonly used for window & weights).
- Q6.10: Used for log and MFCC coefficients (6 integer, 10 fractional bits) — stored in signed 16-bit.

**Python: prepare ROMs and test data (example)**

1. Install dependencies (recommended in a virtualenv):

```powershell
python -m pip install --upgrade pip
pip install numpy scipy librosa soundfile tensorflow scikit-learn
```

2. Generate ROMs and a reference MFCC (creates `roms/`):

```powershell
python generate_roms_and_ref_2048.py
```

3. Convert an input WAV to samples and hex for the TB:

```powershell
# Put your 1-second WAV as input.wav in repo root
python wav_to_pcm16.py        # writes audio_samples.txt
python dec_to_hex.py         # reads audio_samples.txt, writes audio_samples.hex
```

The testbench `tb_mfcc.v` expects `python/audio_samples.hex` relative to the simulation working directory. You can move or copy the generated `audio_samples.hex` to `python/audio_samples.hex` or edit the testbench path.

**Simulation (suggested flows):**

- Using Icarus Verilog (simple, open-source):

```powershell
# Install iverilog on Windows (e.g., via Chocolatey or WSL) and run
iverilog -o tb_mfcc.vvp tb_mfcc.v mfcc_top.v windowing.v mel_bank_40.v log_lut.v dct_13x40.v fft_ip_wrap.v && vvp tb_mfcc.vvp
```

Notes:

- `fft_ip_wrap.v` depends on vendor FFT IP (`xfft_0`) which typically isn't simulatable with iverilog. For RTL-only simulation, replace `fft_ip_wrap.v` with a behavioral FFT model or a precomputed dump of FFT outputs.
- The repo expects a `magnitude_approx` module (not included here) that converts complex FFT outputs to magnitudes. Provide this module or adapt the pipeline for your FFT model.

**Training & Inference (Python):**

- `speech_recogn.py` contains a Colab-converted end-to-end example that:
  - Computes MFCCs using `librosa` with matching parameters (N=2048, hop=512, n_mels=40, n_mfcc=13, TARGET_TIME_STEPS=32).
  - Trains a small CNN (`tinyconv`) for a subset of speech commands and saves `tinyconv_kws_model.h5`.
  - Shows how to load the model and run inference on a single WAV file (the audio must be processed with the same MFCC function used for training).

To run training (on Colab or local machine with GPU):

```powershell
python speech_recogn.py
```

**File-by-file summary (quick reference):**

- `wav_to_pcm16.py`: Read WAV → write `audio_samples.txt` (decimal int16 per line).
- `dec_to_hex.py`: Convert `audio_samples.txt` → `audio_samples.hex` (hex lines for testbench).
- `generate_roms_and_ref_2048.py`: Create ROMs & `ref_mfcc.txt` for test/verification.
- `mfcc_top.v`: Top-level streaming MFCC generator (use `start_clip` to capture 1s audio).
- `windowing.v`: Sliding window + windowing (FRAME_SIZE=2048, HOP=512).
- `fft_ip_wrap.v`: Vendor FFT wrapper (AXI-Stream) — replace or mock for open-source sims.
- `mel_bank_40.v`: Multiply mags by mel weights → 40 mel energies.
- `log_lut.v`: LUT based log approximation (synthesizable priority-encoder normalization + LUT index).
- `dct_13x40.v`: Produces 13 MFCCs from 40 log-mel values.
- `tb_mfcc.v`: Testbench that drives `mfcc_top` with `python/audio_samples.hex` and writes `mfcc_output.txt`.

**Verification tips & debugging:**

- Use `generate_roms_and_ref_2048.py` to create `roms/ref_mfcc.txt` — this provides expected MFCCs for a synthetic frame and helps verify RTL outputs (match Q-formats when comparing).
- When comparing RTL MFCC outputs to Python reference, ensure both are in the same Q-format (the repo uses Q6.10 for MFCCs in RTL and the generator quantizes references to Q6.10).
- If using Icarus Verilog, stub `xfft_0` with a behavioral model that reads precomputed FFT outputs or produces consistent outputs so the rest of the pipeline can be verified.
